Databases

  

  

    
DatabaseSizeWrite-ahead logSchema
      ReclaimableRecordsPlannerIntegrityLast done

    
  

  

  

  

  

    Write-ahead log is what has been written and not yet folded into the file; SQLite folds it in
    by itself, and Checkpoint does it now. Schema is the version the file holds against the
    one this build expects. Reclaimable is space a vacuum would return to the disk, and
    Vacuum returns it: the file is rewritten, which needs about twice its size free and holds
    writes to it until it is done. Planner says whether SQLite has statistics to choose indexes
    by; Optimize gathers them, and again whenever the data has changed shape.
    Check reads every page and every index and can take a while on a large file. Space reads
    every page too. Last done is the newest of each on record, by the page or the schedule, across
    restarts. A vacuum of refs.db also switches it to incremental auto-vacuum, after which the
    fragment sweep hands freed pages back by itself. From a shell:
    kompressor db status, kompressor db check,
    kompressor db checkpoint.

Retention

  

  

    
WhatRuleRunsLast runIt removedNow

    
  

  

  

    What keeps the databases from growing without bound. Requests older than
    stats.retention_days are archived into daily rollups, which are kept, and then
    removed; expired fragments are swept out of the ref store every refs.purge_interval, and the
    pages they held handed back to the disk. With stats.context_retention_days set, requests older
    than that keep their row and lose their copy of the settings, most of a busy stats.db; the
    analysis history is archived first, so no breakdown loses a request. The planner's statistics are
    refreshed every maintenance.optimize_every. Last run is since the service started.

Backup

  
Loading…

  
  

  

  

  

    One gzipped tar with a consistent snapshot of every database above and a
    manifest.json. The snapshots are taken through SQLite while the service keeps running;
    nothing is paused. The configuration and the interception CA are not included: they hold keys.
    The same archive from a shell, for a scheduled job: kompressor backup --out DIR.
  

  
Scheduled backups

  
Loading…

  

    
ArchiveTakenSizeVerified

    
  


  

    Verify checks an archive as a restore would — the checksum written beside it when it was taken, its
    manifest, and a full integrity check of every database in it — without stopping or touching anything. It
    unpacks into the backup directory for as long as it runs. Each archive has a .sha256 beside it:
    a copy taken off this host is checked with sha256sum -c.
  

  
Off-site copy (S3-compatible storage)

  
Loading…

  

    
    
    
  

  

  

  

    
Archive in the bucketTakenSize

    
  

  

    Copies each scheduled archive, and its .sha256, to a bucket on AWS S3, MinIO, Cloudflare R2,
    Backblaze B2, Wasabi or any other S3-compatible store, so a dead disk does not take the backups with it.
    It is off until [maintenance.s3] is set (enabled, bucket,
    access_key_id, secret_access_key, and endpoint for anything but AWS);
    the key is never shown here. To restore, fetch an archive with any S3 client, check it with
    sha256sum -c, and follow Restore below. The bucket should be private: an archive holds every
    tenant's data.

Restore

  

    Restoring replaces the databases, so it is done from a shell on this host with the service
    stopped — not from this page. The command refuses a database that is still open, checks the
    archive in full before touching anything, and moves the files it replaces aside
    (…before-restore-<time>) instead of deleting them.

    Every field given narrows it: requests from before a day, of a tenant, recorded under a run or an experiment
    label (stats.run_id, stats.experiment_id). Trimming keeps every request and
    empties only its copy of the effective settings; the analysis history is archived first, so nothing it
    reports changes. Deleting by a day alone is retention brought forward — each day is rolled up first,
    as the hourly pass would — while deleting a tenant's, a run's or an experiment's requests makes them not to

    what it reports is exact. Freed space is reused by what is written next; Vacuum above hands it back to
    the disk. Trimming is an action (maintenance.actions); deleting is the danger zone's
    (maintenance.erase).
