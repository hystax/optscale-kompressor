Databases

DatabaseFileSizeWrite-ahead logSchema ReclaimableRecordsPlannerIntegrity

Write-ahead log is what has been written and not yet folded into the file; SQLite folds it in by itself, and Checkpoint does it now. Schema is the version the file holds against the one this build expects. Reclaimable is space a vacuum would return to the disk, and Vacuum returns it: the file is rewritten, which needs about twice its size free and holds writes to it until it is done. Planner says whether SQLite has statistics to choose indexes by; Optimize gathers them, and again whenever the data has changed shape. Check reads every page and every index and can take a while on a large file; its result is kept until the service restarts. Space reads every page too. From a shell: kompressor db status, kompressor db check, kompressor db checkpoint.

Where the space is

Table or indexRowsSizeShareUnused inside

Unused inside is slack within the pages a table holds, as distinct from Reclaimable above, which is whole pages holding nothing. A vacuum returns all of the second and only some of the first: rows that nearly fill a page leave the rest of it empty.

Retention

WhatRuleRunsLast runIt removedNow

What keeps the databases from growing without bound. Requests older than stats.retention_days are archived into daily rollups, which are kept, and then removed; expired fragments are swept out of the ref store every refs.purge_interval. Last run is since the service started.

Restore

Restoring replaces the databases, so it is done from a shell on this host with the service stopped — not from this page. The command refuses a database that is still open, checks the archive in full before touching anything, and moves the files it replaces aside (…before-restore-<time>) instead of deleting them.

    Danger zone

    This deletes every statistic this deployment has recorded, for every tenant: every request, compression and retrieval, and the daily rollups that outlive retention. Every dashboard starts again from empty. It cannot be undone from here — only by restoring a backup.

    Stored fragments (refs.db), the record of backups, the configuration and the backup archives are left alone. The service keeps running and goes on recording into the emptied database. Off unless maintenance.erase = true.
